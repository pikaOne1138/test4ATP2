## 第三部分：跨案例 Pattern Analysis

以下是根據候選案例的類型與一般設計實務提出的**待驗證模式與模板建議**，不宣稱已統計上述網站的實際出現頻率。

### 3.1 導航列：優先處理「訪客下一步」，不是功能數量

| 模式 | 知識／部落格 | 助人者 | 初學者模板判斷 |
|---|---|---|---|
| Logo＋少量文字連結 | 很適合 | 很適合 | 預設採用 |
| 右側單一 CTA | 適合訂閱型作者 | 適合合作／初談 | 預設採用；避免兩個主按鈕 |
| 主題分類放第一層 | 主題明確、內容多時適合 | 通常不需要 | 超過約 30 篇再評估 |
| Sticky header | 有助跨頁導航 | 有助找到聯絡入口 | 可選，保持低高度 |
| Transparent header | 容易干擾閱讀 | 可搭大圖，但對比風險高 | 不預設 |
| 滾動後改背景 | 視覺收益有限 | 可用於攝影型首頁 | 進階選項 |
| Mega menu | 小型部落格不需要 | 個人服務不需要 | 不加入 |
| 手機漢堡選單 | 適合 | 適合 | 必做，需鍵盤與焦點管理 |
| 手機底部導航 | 通常不必要 | 容易像 App 或銷售頁 | 不預設 |
| 深淺色切換 | 部分讀者有需求 | 非核心需求 | A 可選；B 先不做 |
| 語言切換 | 有真實雙語內容才需要 | 有真實双語服務才需要 | 不做裝飾性切換 |
| 搜尋 | 文章多時有價值 | 小型網站通常不需要 | A 可選；B 不預設 |

### 3.2 首頁排版：內容型與服務型不能套同一個公式

#### 知識／部落格建議順序

| 順序 | 區塊 | 是否必要 | 設計判斷 |
|---|---|---|---|
| 1 | 簡短作者定位 | 必要，但不一定是大型 Hero | 一兩句說清楚寫什麼、為誰寫 |
| 2 | 精選文章或最新文章 | 必要 | 首屏或緊接首屏就應看見真實內容 |
| 3 | 最新文章清單 | 必要 | 若前一區已是最新清單，不再重複 |
| 4 | 主題入口 | 有足夠內容時加入 | 先有文章，再有分類 |
| 5 | 短版 About | 建議 | 支援作者信任，不取代完整 About |
| 6 | 電子報 | 有實際訂閱服務才加入 | 說清楚內容、頻率與退訂方式 |
| 7 | Footer | 必要 | 次要導航、RSS、社群、法律資訊 |

**看起來更精緻的做法：**

- 一篇較大的精選文章＋一組純文字清單。
- 使用細分隔線、日期與標籤建立秩序，而不是每篇都放陰影卡片。
- 圖片只用在有視覺價值的文章。
- About 與電子報不必都做成巨大背景色區塊。

**容易變成罐頭的做法：**

- 大 Hero → 三個價值 icon → 三欄特色 → 三篇文章 → 三張推薦語。
- 最新、熱門、精選各放一列，但內容高度重複。
- 尚未有文章，就先放六個空分類。
- 用抽象口號取代具體內容定位。

#### 助人者建議順序

| 順序 | 區塊 | 是否必要 | 設計判斷 |
|---|---|---|---|
| 1 | 身分、服務對象、合作入口 | 必要 | 訪客應立刻知道你是誰、能提供什麼 |
| 2 | 適合討論的需求／服務範圍 | 必要 | 用具體情境，不用恐懼放大式痛點 |
| 3 | 服務方式與基本資訊 | 必要 | 線上／實體、時間、地點、費用或查詢方式 |
| 4 | 方法與工作理念 | 建議 | 說明合作如何進行，不堆術語 |
| 5 | 個人介紹與專業資格 | 必要 | 資格可查核；人物照片自然可信 |
| 6 | 合作流程 | 必要 | 了解 → 聯絡／預約 → 確認 → 開始 |
| 7 | 精選資源／文章 | 有內容時加入 | 提供不必立刻付費的理解入口 |
| 8 | FAQ | 建議 | 處理費用、保密、取消、適合性等疑問 |
| 9 | 低壓力聯絡 CTA | 必要 | 告知下一步、回覆時間與界線 |
| 10 | Footer | 必要 | 聯絡、專業資訊、隱私與緊急求助界線 |

**不一定需要獨立區塊：**

- 「你是否正在經歷……」可以融入服務對象，不必做成焦慮清單。
- 「專業資歷」可以放在 About 與首頁短介中。
- 「適合對象」與「我可以怎麼幫你」常能合併。
- Testimonials 不是心理健康網站的必要條件。

**較高級的感覺通常來自：資訊選擇、文字品質、人物可信度、攝影一致性、留白與字級層級。不是多加三個 Section。**

- 所有文字與按鈕狀態檢查 WCAG 對比；尤其不要把 Muted text 再加低透明度。

### 3.4 精緻感小動畫

這些是**模板動畫規格建議**，不是逐站蒐集後的實測時間值。

| 效果 | 放哪裡 | 時間／easing | 距離／幅度 | 手機與效能 | 實作／是否納入 |
|---|---|---|---|---|---|
| 連結底線展開 | Navbar、文字 CTA | 160–200ms；ease-out | 橫向 0 → 100% | 手機改用明確點擊狀態；成本低 | CSS／建議 |
| 按鈕箭頭滑動 | 次要 CTA | 160–200ms；ease-out | 3–4px | 不依賴 hover 傳達功能；低 | CSS／建議 |
| 按鈕色彩過渡 | 所有按鈕 | 120–180ms；ease-out | 無位移 | 手機適合；低 | CSS／必做 |
| 卡片輕微抬升 | 可點擊文章卡片 | 180–220ms；ease-out | Y −2px | 手機不需要；低 | CSS／可選 |
| 圖片微放大 | 有圖片的文章卡片 | 240–320ms；ease-out | 1 → 1.02 | 觸控不啟用；低 | CSS／可選 |
| Hero 初始淡入 | 首頁短介、人物圖 | 250–400ms；ease-out | 0–6px | 適合；不能延遲主要內容 | CSS／可選 |
| 滾動 fade-up | 非關鍵區塊 | 300–450ms；ease-out | 8–12px | 少量使用；低至中 | JS 觸發／進階 |
| Stagger reveal | 最多 3–4 個內容項目 | 每項 250–350ms；延遲 40–60ms | 6–8px | 不用於長文章清單 | CSS 初始／JS 滾動；進階 |
| 導航背景柔化 | Sticky header | 狀態變更 150–200ms | 無 | Blur 可能增加合成負擔 | CSS；滾動切換常需 JS／可選 |
| Sticky TOC | 長篇文章旁欄 | 無動畫 | 無 | 手機改為可展開目錄 | CSS／長文可選 |
| Reading progress | 長文頂端細線 | 隨滾動，不另加延遲 | 0 → 100% | 適合；不要遮擋內容 | CSS 新特性或 JS／非首版 |
| Smooth anchor | TOC、頁內導航 | 交由瀏覽器處理 | 無固定距離 | 適合；避開 sticky header 遮擋 | CSS／建議 |
| 引文或文字底色過渡 | 少量重點提示 | 180–250ms；ease-out | 無 | 可以；勿造成正文閃動 | CSS／可選 |

| 頁面轉場 | 文章列表 → 文章 | 150–200ms；ease-out | 僅淡入淡出 | 要測導覽與焦點 | 瀏覽器 API／Astro 整合；進階 |
| Subtle parallax | 少量裝飾圖片 | 隨滾動 | 不超過約 12px | 手機停用；可能不適 | JS／不納入 |
| 漸層緩慢移動 | 純裝飾背景 | 12–20 秒循環 | 極低幅度 | 無助閱讀、持续耗能 | CSS／不納入 |

**第一版只保留五種：**按鈕色彩、連結底線、箭頭位移、可選卡片 hover、平滑錨點。

#### 無障礙底線

- 尊重 `prefers-reduced-motion`：取消位移、縮放、視差、平滑捲動與非必要轉場。
- 内容預設可見；JavaScript 失敗時不能整頁透明。
- 不以動畫順序決定可讀性。
- hover 效果不能是唯一的狀態提示；鍵盤 focus 需同樣清楚。
- 不動畫化長文正文、閱讀中的段落或整張首頁。
- 優先動畫 transform 與 opacity，避免反覆改動會造成 layout 的屬性。

### 3.5 CTA：信任型服務不等於把所有按鈕寫得含糊

沒有即時頁面查核，以下不能視為上述案例的逐字 CTA 引用；它是依不同服務路徑整理的文案與轉換建議。

| CTA | 適合情境 | 問題或注意事項 |
|---|---|---|
| 立即購買 | 已充分說明的書籍、課程、數位商品 | 不適合首次接觸的心理服務入口 |
| 立即預約 | 訪客已看過條件、費用與流程 | 放在首頁最上方可能過早 |
| 了解合作方式 | 第一次接觸個人顧問／助人者 | 適合低壓力首頁主入口 |
| 看看這項服務是否適合你 | 服務需要適配評估 | 稍長，適合服務摘要下方 |
| 預約初談 | 確實提供初談且條件明確 | 必須交代費用、時長及性質 |
| 從這裡開始 | 搭配明確的新訪客導引 | 單獨使用過於模糊 |
| 與我聊聊你的需求 | 顧問、教練、一般專業服務 | 心理服務需交代聯絡渠道與保密限制 |
| 了解服務與預約流程 | 有正式預約規範的服務 | 清楚，比「立即改變人生」可信 |
| 查看費用與常見問題 | 尚有疑慮的訪客 | 很好的次要 CTA |

#### 知識／部落格 CTA 層級

| 層級 | 建議 | 位置 |
|---|---|---|
| Primary CTA | 訂閱每月文章整理 | Navbar、文章結尾 |
| Secondary CTA | 閱讀精選文章／探索主題 | 首頁與分類入口 |
| Low-pressure CTA | 查看往期內容／透過 RSS 追蹤 | 訂閱附近、Footer |

如果網站主要目標是閱讀而非名單累積，**「閱讀文章」可以是 Primary CTA**，訂閱降為次要。

#### 助人者 CTA 層級

| 層級 | 建議 | 位置 |
|---|---|---|
| Primary CTA | 了解合作方式；服務頁下方再用「預約初談」 | 首頁 Hero、服務頁末尾 |
| Secondary CTA | 查看服務範圍／認識我的工作方式 | 首頁服務與 About 附近 |
| Low-pressure CTA | 閱讀相關文章／查看常見問題 | 服務頁、FAQ 前後 |

#### 建議的轉換路徑

**首頁 → 服務說明 → 適合與不適合的情況 → 費用與流程 → FAQ → 預約／聯絡。**

不是：

**首頁 → 立刻交出電話與心理困擾 → 等待銷售聯絡。**

#### 助人者網站的信任與倫理

- 不預設倒數計時、名額焦慮、保證效果或「一次解決創傷」。
- 心理師與其他助人工作者的資格、範圍不能混用。
- 心理健康服務不應預設使用個案推薦語；需考量法規、倫理、保密與權力關係。
- 可用專業資格、工作經歷、可查核研究、公開出版與明確流程代替見證。
- 表單只蒐集完成聯絡所需的最少資訊，避免開放填寫大量敏感病史。
- 明確說明回覆時間、不是即時危機支援，以及適用地區的求助資源。

### 3.6 文章頁：Astro 模板真正應該做好的核心

#### 建議優先檢視的文章案例

- **Huli’s Blog**：中文長文、技術文字與程式碼。
- **Josh W. Comeau**：教學文章與特殊內容元件。
- **Gwern**：長文導航、註腳與交叉參照；只借必要部分。
- **Craig Mod**：攝影、文字與作者感。
- **The Marginalian**：引文、圖片與長篇敘事。
- **Derek Sivers、Zen Habits**：純文字閱讀的最低必要結構。

#### 閱讀尺寸建議

| 項目 | 建議規格 |
|---|---|
| 正文最大寬度 | 約 680–740px；以實際中文字體測試 |
| 中文行長 | 約 32–40 個全形字，避免超寬 |
| 正文字級 | 手機 18px；桌機 18–20px |
| 中文行高 | 1.8–1.95 |
| H1 | 手機 32–40px；桌機 44–56px |
| H2 | 26–32px |
| H3 | 22–26px |
| 段落間距 | 約 1–1.3em |
| 大節之間 | 約 40–56px |
| 圖說 | 14–16px，對比足夠 |
| TOC 欄 | 桌機約 200–240px；不壓縮正文 |

`ch` 單位主要反映字型中「0」的寬度，**不能直接把英文的 65ch 當成中文理想行長**。

#### 必備／加分／先不做

| 元素 | 優先級 | 原因與建議 |
|---|---|---|
| 標題、摘要或引言 | 必備 | 讓讀者確認文章是否符合需求 |
| 發布日期 | 必備 | 提供時間背景 |
| 作者資訊 | 必備，但不必每篇巨大卡片 | 單一作者可用精簡署名 |
| H2／H3 層級 | 必備 | 讀者掃讀與螢幕閱讀器導覽 |
| 圖片替代文字 | 必備 | 有意義圖片需提供文字替代 |
| Figure caption | 依內容必備 | 說明圖片、來源與授權 |
| 連結、列表、Quote | 必備 | 基本內容語義 |
| 更新日期 | 加分；知識內容強烈建議 | 不能每次部署都自動改日期 |
| Category | 加分 | 建議一篇一個主分類 |
| Tag | 加分 | 避免大量只有一篇文章的標籤 |
| TOC | 長文必備、短文省略 | 由標題自動產生 |
| Sticky TOC | 加分 | 桌機限定，長目錄需可捲動 |
| 閱讀時間 | 加分 | 是估算，不假装精準 |
| Callout | 加分 | 先做提示、注意兩種即可 |
| 相關文章 | 加分 | 2–3 篇，依主題或人工設定 |
| 上一篇／下一篇 | 加分 | 系列內容比純日期排序更有用 |
| Newsletter CTA | 有電子報時加分 | 放文章結尾，不中途打斷 |
| Code block | 技術文章必備，其他可選 | 手機局部橫捲，不讓整頁溢出 |
| Footnote | 研究文章加分 | 回跳連結與觸控範圍要清楚 |
| Reading progress | 先不做 | 不會比清楚 TOC 更重要 |
| 分享按鈕 | 先不做 | 可先提供「複製連結」 |
| 社群浮動分享條 | 不建議 | 遮擋手機、增加干擾 |
| 留言與會員登入 | 不建議第一版 | 審核、垃圾留言與隱私成本 |
| 懸浮註腳預覽 | 不建議第一版 | 跨裝置與鍵盤互動較複雜 |

## 第四部分：兩套模板 Design Brief

====================  
模板 A｜知識／部落格  
====================

### 1. 核心風格

**Warm Editorial：安靜、有編輯感、作者辨識清楚。**

米白底、深色正文、襯線標題、細邊線。不以漸層、玻璃或大量盒裝卡片製造設計感。

### 2. 目標使用者

個人知識整理者、創作者、專業文章作者、長期經營內容的自由工作者。

適合文字先行，不要求每篇都準備封面圖。

### 3. Sitemap

- 首頁
- 文章列表
- 主題列表／各主題頁
- 單篇文章
- 關於
- 資源，可選
- 訂閱說明，可選
- 隱私政策，有蒐集資料時需要

### 4. Navbar

[作者名]　文章｜主題｜關於　　　　[訂閱電子報]

沒有電子報時，移除訂閱按鈕，不用「聯絡」強行替代。

### 5. Homepage Sections

1. 作者定位：兩句以內。
2. 精選文章：一篇，可帶圖。
3. 最新文章：4–6 篇，以文字清單為主。
4. 主題入口：3–5 個，有內容才出現。
5. 短版 About。
6. Newsletter，可選。
7. Footer。

### 6. Article layout

正文最大寬約 720px；標題、引言、日期、作者、主分類置於開頭。

長文提供 TOC；桌機可在右側 sticky，手機在正文前展開。結尾放相關文章與一次訂閱 CTA。

### 7. About page

- 我是誰。
- 我關注哪些問題。
- 這個網站會寫什麼。
- 背景與經歷。
- 推薦新讀者先看哪些文章。
- 聯絡方式。

避免只有履歷，也避免只有抽象人生宣言。

### 8. CTA

主：訂閱文章整理。  
次：閱讀精選文章。  
低壓力：查看往期內容、RSS。

### 9. Color palette

採用 **Editorial Magazine**：

背景 #F6F3ED、Surface #FFFFFF、正文 #25221F、次要文字 #66605A、Accent #8C3B2F、Hover #6F2D24、Border #D9D2C7。

### 10. Typography

標題 Noto Serif TC；正文 Noto Sans TC。

第一階段只載入必要字重；如果效能或教學負擔太高，全部使用 Noto Sans TC。

### 11. Buttons

主按鈕實色、小圓角；次按鈕採文字＋箭頭。

不預設膠囊形、不加發光陰影、不做大幅縮放。

### 12. Cards

兩種即可：

- 文字文章列：標題、摘要、日期、分類。
- 圖文精選卡：一張圖片＋文字。

不讓首頁每區都變成相同三欄卡片。

### 13. Images

封面圖可選；統一比例與裁切焦點。

無圖文章應保留同等品質的版面，不生成假封面補位。

### 14. Micro animations

底線展開、箭頭 3px 位移、按鈕色彩過渡。

圖片 hover scale 可選；不做逐段文章 reveal。

### 15. Mobile behavior

- 單欄內容。
- 正文 18px 起。
- TOC 折疊。
- Code block 局部橫捲。
- 選單可鍵盤操作。
- 不做底部浮動訂閱條。

### 16. Footer

作者名／一句定位、文章、About、RSS、社群、版權；有表單時補隱私政策。

### 17. 必做元件

Header、Mobile menu、Article list、Article header、Prose、Footer、SEO metadata、404。

### 18. 可選元件

TOC、Tag、Related posts、Newsletter、Callout、Figure、Code block、RSS、搜尋。

### 19. 不建議加入的功能

會員、留言、數位花園圖譜、互動模擬器、推薦演算法、每頁不同轉場、預設雙主題。

### 20. 最值得參考的 5 個網站

1. **AstroPaper**：技術結構與文章基線。
2. **Derek Sivers**：精簡與作者聲音。
3. **Craig Mod**：Editorial 品牌與圖文節奏。
4. **Huli’s Blog**：繁中長文需求。
5. **Ness Labs**：主題導引與订閱路徑。

====================  
模板 B｜助人者  
====================

### 1. 核心風格

**Calm Professional：溫暖但不模糊，專業但不冰冷。**

自然人物攝影、穩定字級、安靜背景色；避免把所有助人者都做成植物＋月亮＋水晶的相同風格。

### 2. 目標使用者

心理師、諮商相關專業者、教練、顧問、身體工作者及其他個人服務者。

不同資格與服務範圍須能清楚替換，不能預設使用醫療或心理治療用語。

### 3. Sitemap

- 首頁
- 服務與合作
- 單項服務
- 關於我
- 常見問題
- 文章／資源，可選
- 聯絡／預約說明
- 隱私政策
- 服務條款或取消政策，依服務需要

### 4. Navbar

[姓名／品牌]　服務與合作｜關於我｜資源｜常見問題　　　　[了解初談]

不提供初談者改成「了解合作方式」。

### 5. Homepage Sections

1. 姓名、專業身分、服務對象、人物照片。
2. 服務範圍與適合需求。
3. 服務方式與摘要。
4. 工作方法／理念。
5. 關於我＋可查核資格。
6. 合作流程。
7. 精選資源，可選。
8. FAQ。
9. 聯絡 CTA。
10. Footer。

### 6. Service page

必須回答：

- 這是什麼服務。
- 適合誰、不適合誰。
- 可以討論哪些需求。
- 如何進行、多久、在哪裡。
- 費用及付款方式，或清楚的查詢方式。
- 保密與服務限制。
- 取消／改期規定。
- 下一步怎麼做。

不能只放漂亮照片與一句「陪伴你成為更好的自己」。

### 7. About page

人物照片、背景故事、資格、方法訓練、工作經驗、價值觀與服務界線。

把專業資格與個人成長故事分開，不以自身經歷代替資格。

### 8. CTA

首頁主：了解合作方式。  
服務頁主：預約初談／提出合作需求。  
次：查看費用與流程。  
低壓力：閱讀相關資源。

### 9. Color palette

採用 **Warm Therapeutic**：

背景 #F8F5EF、Surface #FFFCF8、正文 #292724、次要文字 #706B64、Accent #8B5138、Hover #70402C、Border #DDD5C9。

### 10. Typography

標題 Noto Serif TC；正文 Noto Sans TC。

短標題有襯線氣質，服務資訊與表單保持清楚易讀。

### 11. Buttons

實色主按鈕、清楚焦點框、適當觸控尺寸。

不使用「立即蛻變」「搶救人生」等誇大文案。

### 12. Cards

服務卡只顯示：名稱、適合對象、方式、下一步。

資格、流程與 FAQ 優先用文字與列表，不全部塞進卡片。

### 13. Images

主圖以真實人物為主；室內環境與細節照片為輔。

沒有照片時可用文字版 Hero，不拿陌生人的肖像假裝服務提供者。

### 14. Micro animations

按鈕過渡、底線、箭頭微移動；人物圖最多輕微初始淡入。

不做視差人物、不做滿頁浮動裝飾。

### 15. Mobile behavior

- 姓名、服務身分與合作入口在上方可見。
- 不讓大照片把服務資訊推到兩屏之外。
- 服務卡直列。
- FAQ 可折疊，但關鍵費用與限制不能只藏在 FAQ。
- 不預設黏住底部的大型預約按鈕。

### 16. Footer

姓名、資格／服務類型、地區或線上方式、聯絡、回覆時間、隱私政策、取消規範。

適用時明確寫出：此聯絡方式不是緊急求助渠道。

### 17. 必做元件

Header、Mobile menu、Hero、Service summary、Professional bio、Credentials、Process、FAQ、Contact CTA、Footer。

### 18. 可選元件

文章、資源下載、Newsletter、外部預約入口、多語內容、地圖、媒體曝光。

### 19. 不建議加入的功能

自行開發預約系統、會員病歷、敏感心理問卷、即時聊天、倒數促銷、保證成效、預設個案見證輪播。

### 20. 最值得參考的 5 個網站

1. **Lori Gottlieb**：個人專業與作者身分的尺度。
2. **Esther Perel**：Editorial 人物品牌。
3. **Kristin Neff**：方法與依據的信任呈現。
4. **cotree**：服務流程與預約前資訊。
5. **FarHugs 遠距抱抱**：繁中服務說明與求助情境。

## 第五部分：如果只能各做一套模板，最值得融合哪些網站的哪些元素？

### A. 知識／部落格：融合 5 個案例

| 案例 | 借用部分 | 明確不借 |
|---|---|---|
| AstroPaper | Astro 內容結構、文章列表、基礎頁面 | 把所有可選功能都納入教學 |
| Derek Sivers | 少量導航、精簡作者定位、文字優先 | 過度削弱主題導覽 |
| Craig Mod | 襯線標題、攝影與文字的編輯思路 | 高攝影依賴、複雜出版銷售 |
| Huli’s Blog | 中文長文、程式碼與內容密度需求 | 技術文章專用的所有功能 |
| Ness Labs | 主題導引、文章到訂閱的關係 | 會員、社群、課程平台 |

**收斂方向：一個能在「沒有封面圖」時仍然好看的 Warm Editorial 部落格。**

教學的主要修改面應只有：

- 作者資訊。
- 文章內容。
- 主題分類。
- 一組色彩 Token。
- 一至兩個字體家族。
- 可選的訂閱入口。

### B. 助人者：融合 5 個案例

| 案例 | 借用部分 | 明確不借 |
|---|---|---|
| Lori Gottlieb | 個人專業網站的內容尺度、身分介紹 | 作者品牌的大量媒體內容 |
| Esther Perel | 人物辨識、觀點與方法的 Editorial 表達 | 影音庫、會員與大型內容產品 |
| Kristin Neff | 清楚方法、可查核依據、免費理解入口 | 複雜課程與研究資源系統 |
| cotree | 適合性、流程、預約前減少疑慮 | 配對、登入與平台功能 |
| FarHugs 遠距抱抱 | 中文服務語氣、基本服務資訊 | 平台級表單與帳號架構 |

**收斂方向：一個讓訪客先理解「是否適合、如何合作」，再決定是否聯絡的 Calm Professional 個人服務網站。**

教學的主要修改面應只有：

- 姓名、照片、資格與服務範圍。
- 一至三項服務。
- 費用／流程／服務限制。
- FAQ。
- 外部聯絡或預約連結。
- 一組色彩 Token。

**兩套模板最重要的共同原則：把精緻感做在排版、文字、資訊順序與可靠互動上；把複雜功能留在模板之外。**
