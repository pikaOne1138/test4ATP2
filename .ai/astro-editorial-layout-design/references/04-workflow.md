# AI 生成工作流程（八步，每步有產出物與出口條件）

> 核心禁令：**不得把既有網站變成「只有配色不同的共用模板」。** 每個新站必須在構圖旋鈕上與十款中任何一款至少 3 個不同（`checklists/diversity-check.md`）。

```
1 需求理解 → 2 選版型方向 → 3 wireframe → 4 tokens+結構 → 5 Astro 實作 → 6 截圖檢查 → 7 修正 → 8 交付
        ↑______________________ 6 失敗則回到 4 或 3，而不是只改 CSS ____________________|
```

## 1. 需求理解（產出：`brief.md`）

必填欄位（缺就問使用者，或明確標「假設」）：

| 欄位 | 內容 | 例 |
|---|---|---|
| 站長是誰 | 一句話 | 「獨立書評人，每年讀 120 本」 |
| 訪客第一個問題 | 他們帶著什麼來 | 「這個人的推薦值得信任嗎？」 |
| 要被怎樣信任 | 證據類型 | 作品、方法、範圍、資格、紀錄 |
| 唯一主動作 | 1 個 | 「訂閱年度書單」 |
| 內容層級表 | 每區塊：主張／證據／下一步 | 見下 |
| 誠實限制 | 哪些資訊尚未提供 | 資格、見證、價格＝佔位 |
| 品牌語氣 | 3 個詞＋1 個**不要**的詞 | 安靜、具體、不說教／不要「專業賦能」 |

**內容層級表**範本（至少 5 列）：

| 區塊 | 主張（標題要寫成一句話） | 證據（真實或標示佔位） | 下一步 |
|---|---|---|---|

**出口條件**：每個標題都是具體主張（非「關於我們」「服務項目」）；助人類站已寫出「適合／不適合」與緊急資源。

## 2. 選版型方向（產出：`direction.md`）

1. 讀 `references/01-cross-site-patterns.md` §E，**對 8 個旋鈕各選一值**。
2. 與十款比對：寫出「最接近的 2 款」及「我們在哪 ≥ 3 個旋鈕上不同」。
3. 從 `recipes/` 各選：1 個 Hero、2–3 個內容分區、1–2 個列表、2 個節奏、1 個 CTA／信任安排。
4. 寫一句話：**「為什麼這個構圖適合這位站長」**（不能用形容詞；要寫成結構理由，如「訪客需要先看到他一年讀過的書，所以 hero 是書單本身」）。

**出口條件**：旋鈕表完整；與最近兩款差異 ≥ 3 個旋鈕。

## 3. Wireframe（產出：`wireframe.md`，ASCII）

- 畫**1440 與 390 兩張**；標上每個區塊的 grid 欄比與最大寬度。
- 每個區塊標：配方 ID、標題字級（`clamp()`）、主要對齊軸。
- 標明**手機的重排規則**：哪欄先、哪欄隱藏（不是縮小）、斷點。

範例：
```
1440 (container 1320, gutter 64)
┌ header 84px ─────────────────────────────┐
│ [kicker mono 12px]                        │
│ H1 11vw / lh 1.0 ─ 2 行 (8 欄)  │ 圖 3 欄 │
│ deck 1.15rem max 34em ─────────────────── │
├ section gap 96 ───────────────────────────┤
│ .7fr 標題 │ 1.3fr 列表 (L01 ledger)        │
```

**出口條件**：每個區塊有配方 ID 與手機規則；有一個「視覺焦點」（每屏只有 1 個）。

## 4. Tokens 與結構（產出：`tokens.css`、頁面骨架）

- 依 `references/02-design-tokens.md` 填 `--ed-*` 變數：gutter、字級階（≤ 9 個命名角色；audit 量測 ≤ 12）、間距階、色票（含文字用/裝飾用強調色）、線寬。
- **先跑對比**：`ink/paper`、`ink-2/paper`、`accent/paper`、`paper/panel` 全部 ≥ 4.5:1（大字 ≥ 3:1）。
- 建立語意 HTML 骨架（header / main / section[aria-labelledby] / footer），先不加裝飾。

**出口條件**：無 CSS 時頁面可讀；色票對比表已填。

## 5. Astro 實作

- 一頁一個 scoped `<style>`，**可讀排版（非單行壓縮）**；class 前綴一站一組（如 `al-`）。
- 用 `recipes/code/**` 的成品當起點，**複製後必須改結構**，不是只改文字（否則違反 F10）。
- 資料放 frontmatter 陣列 `.map()`，不要重複貼 HTML。
- 圖片：`aspect-ratio`、`width/height`、`alt`；沒有授權圖就用 SVG/CSS 繪製。
- 互動：優先 `<details>`、`<progress>`、`<audio>`、`:target`；JS 僅 inline、≤ 40 行、無 JS 仍可讀。
- 先通過：`npm run build`。

## 6. 截圖檢查（產出：`audit-out/`）

```bash
npm run dev            # 或 astro preview
node scripts/audit.mjs --base http://localhost:4321 --paths / --out ./audit-out
```
- 四寬度整頁截圖＋ `report.json`。
- **然後實際看截圖**（至少 1440 與 390 兩張的首屏與每個區塊）。工具抓不到的：孤字、構圖失衡、圖片主體被裁、影像上文字可讀性、整體節奏。
- 依 `checklists/visual-qa.md` 逐項打勾，依 `checklists/scoring.md` 計分。

## 7. 修正

- 每個 FAIL／扣分都要對應到**一個結構性修正**（欄比、斷行、順序、隱藏次要欄位），不要只調 padding 與字級。
- 修正後重跑第 6 步；記錄「修正前→後」於 `DECISIONS.md`。
- 兩輪未過 85 分 → 回到第 3 步（wireframe 有問題）。

## 8. 交付

交付物：`src/pages/*.astro`、`tokens.css`、`DECISIONS.md`（構圖決策、旋鈕表、與最近兩款的差異、修正紀錄）、四寬度截圖、audit 報告、`brief.md`（含「尚未提供／佔位」清單）。
**交付訊息必須誠實列出**：已驗證什麼（build、audit、截圖）、未驗證什麼（真實裝置、螢幕閱讀器）、佔位內容清單。

## 禁止事項（快速版）

1. 禁止複製一款的 class 結構再換色。
2. 禁止整頁 <12px 標籤。
3. 禁止只跑 `astro build` 就宣稱完成。
4. 禁止編造資格／見證／數字／日期。
5. 禁止在助人類站使用緊迫語氣（「限時」「立即」「名額有限」）。
6. 禁止一頁出現 ≥ 3 組同結構三欄卡片。
